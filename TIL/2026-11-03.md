## 2. 오늘 배운 개념

### 2-1. Endpoint
- **자원(Resource)이 어디에 위치하는지 나타내는 URL 경로(주소)**
- 예: `/api/users` → 사용자 목록, `/api/v1/users` → 버전이 붙은 사용자 API
- 설계 규칙 (REST)
  - 자원은 **명사 · 복수형 · 소문자** (`/users`, `/order-items`)
  - 행위는 URL이 아니라 **HTTP Method**로 표현 (`/getUsers` ❌ → `GET /users` ✅)
  - 버전 표시(`v1`)로 API가 바뀌어도 기존 사용자가 깨지지 않게 함

### 2-2. HTTP Method (요청 방식)

| Method | 의미 | CRUD | 예시 |
|---|---|---|---|
| GET | 조회 | Read | `GET /api/users` |
| POST | 생성 | Create | `POST /api/users` |
| PUT | **전체** 수정(교체) | Update | `PUT /api/users/3` |
| PATCH | **일부** 수정 | Update | `PATCH /api/users/3` |
| DELETE | 삭제 | Delete | `DELETE /api/users/3` |

- **PUT vs PATCH**: PUT은 통째로 교체(안 보낸 필드는 사라질 수 있음), PATCH는 보낸 필드만 변경
- **멱등성**: 같은 요청을 여러 번 보내도 결과가 같은 성질 → GET·PUT·DELETE는 멱등, **POST는 멱등 아님**

### 2-3. Request (요청)

| 위치 | 예시 | 용도 |
|---|---|---|
| Path Variable | `/users/3` | 특정 자원 하나 식별 |
| Query Parameter | `/search?keyword=apple` | 검색·필터·정렬·페이징 |
| Request Body | `{"name": "홍길동", "drinks": "김렛"}` | 생성·수정할 데이터 (주로 JSON) |
| Header | `Authorization: Bearer ...` | 인증·데이터 형식 등 부가정보 |

- Path Variable과 Query Parameter는 **URL에 붙는 값**
- 비밀번호 같은 민감 정보는 URL이 아니라 **Body**로 보낸다

### 2-4. Response (응답)
- **상태코드(성공 여부) + 데이터 본문**으로 구성
- 2xx 성공 · 3xx 리다이렉션 · **4xx 클라이언트 잘못** · **5xx 서버 잘못**

| 코드 | 의미 |
|---|---|
| 200 OK | 성공 |
| 201 Created | 생성 성공 (POST) |
| 204 No Content | 성공, 본문 없음 (DELETE) |
| 400 Bad Request | 요청 형식 오류 |
| 401 Unauthorized | 인증 실패 — "누구세요?" |
| 403 Forbidden | 권한 없음 — "알지만 안 돼요" |
| 404 Not Found | 자원 없음 |
| 500 Internal Server Error | 서버 오류 |

### 2-5. API 보안

**JWT (JSON Web Token)**
- 로그인한 **사용자**를 증명하는 토큰, `Authorization: Bearer <토큰>`으로 전달
- 구조: `Header.Payload.Signature`
- Payload는 암호화가 아니라 Base64 인코딩 → **비밀번호 등 민감 정보 금지**
- Signature로 위조 여부를 검증, 만료시간(exp)은 짧게

**API Key**
- API를 호출하는 **앱/프로젝트**를 식별하는 키 (`x-api-key` 헤더 등)
- 사용량 집계, Rate Limit에 활용
- 프론트 코드·GitHub에 노출 금지 → **환경변수(.env)** 에 보관

**CORS (Cross-Origin Resource Sharing)**
- 브라우저는 **다른 출처(Origin)** 로의 요청을 기본적으로 막음 (동일 출처 정책, SOP)
- Origin = **프로토콜 + 도메인 + 포트** (예: `localhost:3000` ≠ `localhost:8080`)
- 해결은 **서버**에서 `Access-Control-Allow-Origin` 등 헤더로 허용 출처 설정
- 본 요청 전 `OPTIONS`로 허용 여부를 묻는 **Preflight** 요청이 있음
- 브라우저가 검사하는 것이라 Postman·서버 간 통신에선 CORS 에러가 안 남

## 4. 배포 과정 (GitHub Pages)

```bash

git add .
git commit -m "백엔드 API 기초 공부 사이트 추가"
gh repo create backend-api-study --public --source=. --push   # 저장소 생성 + 업로드
```
